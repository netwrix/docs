# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Product Overview

PingCastle Enterprise documentation. Enterprise is the full platform with a web UI, agents, scheduler, and API. PingCastle is split into three sibling products, each with its own docs tree: `docs/pingcastleenterprise/`, `docs/pingcastlepro/`, and `docs/pingcastlecommunity/`. The first Getting Started page of each states which edition it covers and links to the other two.

## File Structure

- `4.0/` follows the section guide zones: `getting-started/`, `requirements/`, `install/`, `migration/`, `configuration/`, `admin/`, `integrations/`, `troubleshooting/`, with only the zones that apply.
- `3.5/` is the legacy flat layout. Don't restructure it.
- Settings pages sit under `4.0/configuration/settings/`; SCIM is in `4.0/integrations/`.
- `3.5/` holds `install.md`, `upgrade.md`, and `user.md`.

Sidebars are autogenerated (`sidebars/pingcastleenterprise/<version>.js`). Order comes from `_category_.json` and `sidebar_position`.

Images go in `static/images/pingcastleenterprise/<version>/`.

## Knowledge Base

The KB article source is `docs/kb/pingcastleenterprise/`; it is copied into the versioned folders at build time. It covers both Enterprise and Pro, so refer to both editions when you edit it. Open decision for the product owner: it is stored only under Enterprise, so Pro readers don't see it in their sidebar. If it should appear for Pro, add a copy under `docs/kb/pingcastlepro/` (with `_category_.json` and `0-images`). Filenames are lowercase kebab-case describing the exact symptom.

## Terminology

Use these exact product names, and don't abbreviate or invent variants: PingCastle Enterprise, PingCastle Pro, PingCastle Community (also called PingCastle Standard and PingCastle Basic in older material), PingCastle for Service Providers.

"Active Directory" and "Entra ID" are always capitalized. Never use "AD" alone without spelling it out first.
