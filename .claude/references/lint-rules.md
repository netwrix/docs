## Dale (model-checked)

- **collaborative-leftovers**: Fires on chatbot leftovers: 'Certainly, here is...', 'I hope this helps', 'As an AI', 'Let me know if you would like...', 'Feel free to ask', or a knowledge-cutoff disclaimer such as 'as of my last update'. (Message: Remove text that reads like a reply to a prompt.)
- **copula-avoidance**: Fires when 'serves as', 'functions as', 'acts as', 'stands as', 'represents', or 'boasts' is used where a plain 'is/are/has' would say the same thing. Does not fire when the verb describes a real functional role, such as 'acts as a proxy' or 'serves as the gateway between two networks'. (Message: Use 'is' or 'are' instead of 'serves as', 'functions as', 'acts as', or 'stands as'.)
- **excessive-hedging**: Fires when qualifiers are stacked past what a documented, tested behavior warrants, such as 'may potentially', 'could possibly in some cases', 'might in certain circumstances be able to'. (Message: Remove stacked qualifiers on documented behavior.)
- **exclamatory-sentences**: This rule should trigger when the user or agent writes exclamatory sentences. (Message: Don't use exclamatory sentences.)
- **false-range**: Fires when a rhetorical 'from X to Y' or 'ranging from X to Y' span stands in for a real list, such as 'from basic reporting to advanced analytics' or 'ranging from simple fixes to complex overhauls'. Does not fire on real numeric, date, or version ranges. (Message: Name the actual items instead of a rhetorical span.)
- **filler-phrases**: Fires on throat-clearing and filler such as 'It is important to note that', 'It is worth mentioning', 'In today's fast-paced environment', 'needless to say', 'at the end of the day', 'it should be noted that', when the sentence works without it. Does not fire on 'in order to' (a separate wordiness rule covers it). (Message: Cut the throat-clearing; it adds words, not information.)
- **generic-conclusion**: Fires when a closing paragraph or section restates the page's value in vague, feel-good terms (for example 'By following these steps, you can ensure a smooth and efficient experience') instead of ending on the last concrete instruction or fact. Does not fire on a sentence that states the concrete expected result of a step, such as 'The service should now start.' (Message: End on the last concrete instruction or fact.)
- **idioms**: This rule should trigger when the user or agent uses an idiom or other culturally specific expression. (Message: Don't use idioms. Write what you mean more directly and literally.)
- **inflated-significance**: Fires when a sentence inflates the significance of a routine feature or step with phrases like 'plays a crucial/vital/key role', 'serves as a cornerstone', 'is essential to ensuring', 'a testament to'. Does not fire on plain factual statements that something is required (for example 'You must have Domain Admin rights'). (Message: Do not frame a routine feature or step as uniquely important ('plays a crucial role', 'serves as a cornerstone', 'is essential to ensuring'). State what it does.)
- **ing-analysis**: Fires when a sentence states a fact and then tacks on a trailing participle clause or ', which makes/gives/ensures ...' clause that interprets or praises instead of stating a concrete result. Typical openers: ensuring, reflecting, highlighting, underscoring, emphasizing, demonstrating, showcasing, strengthening, making this/it ..., giving you ..., helping you ..., which makes/means .... Examples: 'The scan runs nightly, ensuring your data stays current'; 'The policy applies to all users, highlighting its importance'; 'The engine evaluates each rule, highlighting gaps and reflecting the state of your environment'. If a clause names a specific, checkable effect ('the job writes a log, which you can review under Reports') it is not a violation. Does not fire on '-ing' clauses that describe a concrete action. (Message: Cut the trailing '-ing' clause or replace it with a specific consequence.)
- **minimizing-difficulty**: This rule should trigger when the documentation minimizes task difficulty—for example, 'With [product], you can easily [task].' (Message: Do not minimize the difficulty of tasks users are performing.)
- **misplaced-modifiers**: This rule should trigger when the documentation has a misplaced or dangling modifier. This includes participial phrases that attach to the wrong subject (e.g., '[participle phrase], [wrong subject] [verb]') and modifying clauses placed too far from the word they describe (e.g., '[noun A] [preposition] [noun B] [modifier that actually describes noun A]'). (Message: Avoid misplaced modifiers. Move the modifier, or descriptive phrase, so that it accurately describes the right thing.)
- **negative-assumptions**: This rule should trigger when the user or agent writes something that assumes a user cannot do something without the product. (Message: Don't make negative assumptions about what users can or cannot do.)
- **negative-parallelism**: Fires on negative parallelism: 'not just X but Y', 'not only X but also Y', 'isn't merely X, it's Y', 'this isn't about X, it's about Y'. Does not fire on a plain contrast that conveys real information, such as 'Use the service account, not your personal account'. (Message: Do not use 'not just X, but Y' or 'isn't merely X, it's Y'.)
- **passive-voice**: This rule should trigger when the user or agent writes a sentence or clause in passive voice. (Message: Don't use passive voice. Use active voice instead.)
- **positional-references**: This rule should trigger when the documentation uses spatial direction words like 'below', 'above', 'as shown below', or 'the above section' to reference other content. (Message: Avoid positional references like 'below', 'above', or 'as shown below'. Use 'the following' or a named anchor instead.)
- **promotional-language**: Fires when marketing praise such as powerful, robust, seamless, cutting-edge, industry-leading, game-changing, best-in-class, comprehensive solution is used as unsupported praise rather than a specific, checkable claim. (Message: Replace unsupported praise with a specific, checkable claim.)
- **sycophantic-tone**: Fires on sycophantic phrasing aimed at a requester, such as 'Great question', 'You are absolutely right to ask', 'Excellent choice', 'Good thinking'. (Message: Remove servile or flattering phrasing.)
- **undefined-acronyms**: This rule should trigger when a product-specific or non-standard acronym is used without being spelled out on first use in body prose, following the pattern: 'File System Access Audit (FSAA)' on first use, then 'FSAA' thereafter. Do NOT flag: well-known IT industry standards that a sysadmin audience would know (DNS, AD, IP, HTTP, TCP, SID, UID, CPU, RAM, URL, SQL, OS, VM, API, SSH, SSL, TLS, LDAP, SAML, MFA, ACL, DACL, SACL, OU, GPO, NTFS, etc.); code literals in backticks; Netwrix product short names when the full product name has already appeared in the article; acronyms that appear only in headings or titles (define-on-first-use applies to body prose only). Do flag product-specific acronyms like AIC, FSAA, SPAA, CEE, AMQP when used in body text without prior definition, even if the article's title or subject implies the reader knows them. (Message: Acronym used without being defined on first use. Spell it out: 'Full Name (ACRONYM)'.)
- **vague-attribution**: Fires when a claim is attributed to unnamed people or sources with no citation, such as 'users report', 'many organizations find', 'it is widely recognized', 'experts agree', 'studies show'. (Message: Name the source or drop the claim.)
- **wordiness**: This rule should trigger when the user or agent writes a wordy sentence when a more concise, direct alternative is possible without altering the meaning. (Message: This sentence is wordy. A more concise, direct alternative is possible.)
- **xy-slop**: This rule should trigger when the user or agent writes something in the negative-postive form, for example 'x is not y, x is z'—or similar. (Message: Do not use the 'x is not y, x is z' format.)
