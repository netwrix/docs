# Membership Life Cycle Schedule in Directory Manager

The Membership Life Cycle schedule updates the temporary membership of groups in an identity store. It supports these functions:

- Group owners (primary owner, additional owners, and Exchange additional owners) can set a start and end date to add an object as a temporary member of a group, or to remove a member for a temporary period from group membership. The schedule temporarily adds and removes the object from group membership on the specified dates.
- Managers and peers can join and leave a group temporarily on behalf of other users. When the schedule runs, it adds and removes those users from group membership on the specified dates.
- The schedule runs the Membership Life Cycle policy for the identity store. See [Manage Directory Manager Membership Lifecycle Policies](/docs/directorymanager/11.2/admincenter/identitystore/configure/membershiplifecycle.md).
- The schedule also removes members when group owners inactivate them during group attestation. See [Enable Group Attestation](/docs/directorymanager/11.2/admincenter/identitystore/configure/grouplifecycle.md#enable-group-attestation).

Assume that the Membership Life Cycle schedule runs once a week, for example on Mondays. If an object is to be added to group membership from Wednesday through Friday, Directory Manager doesn't add it. This happens because the schedule didn't run on the specific days for the temporary membership update. Ensure that the schedule runs at a frequency that meets your temporary membership requirements.

Directory Manager generates notifications when the schedule adds or removes users from group membership. See [Manage Membership Life Cycle Notifications](/docs/directorymanager/11.2/admincenter/identitystore/configure/smtpserver.md#manage-membership-life-cycle-notifications).

## Create a Membership Life Cycle Schedule

To create a Membership Life Cycle schedule:

1. In Admin Center, click **Identity Stores** in the left pane.
2. On the Identity Stores page, click the ellipsis button for an identity store and select **Edit**.
3. Click **Schedules** under Settings in the left pane.
4. On the Schedules page, click **Add Schedule** and select **Membership Life Cycle Job**. The Create Schedule page opens.
5. In the Schedule Name box, enter a name for the schedule.

   The Name Preview box displays the schedule name prefixed with \_MembershipLifeCycle\_\_. The schedule appears with this name in email notifications.

6. In the Portal URL dropdown list, select a Directory Manager portal URL to include in notifications generated by the schedule. Users are redirected to this portal to perform any necessary action.
7. In the Scheduler Service Name dropdown list, select a Scheduler service to trigger this schedule.

   The number of services in the list depends on the number of nodes in all Elasticsearch clusters in the environment, because each node has its own Scheduler service. For details, see [Directory Manager Scheduler Service](/docs/directorymanager/11.2/admincenter/service/schedulerservice.md).

   :::note
   When selecting a Scheduler service:

   - The Scheduler service for the Directory Manager instance on which you're creating the schedule is selected by default. However, you can select the Scheduler service of another instance as well.
   - You can change the Scheduler service even after creating the schedule. On the next run, the newly selected Scheduler service triggers the schedule.
   - If the selected Scheduler service fails to trigger the schedule, no other Scheduler service is selected automatically.
   - If you run a schedule manually in Admin Center, the Scheduler service of that instance is used.
   :::

8. Optional. Specify containers as targets for the schedule. The schedule processes all groups in these containers and their sub-containers. To specify containers as targets, follow step 9 in [Create a Group Usage Service Schedule](groupusageservice.md#create-a-group-usage-service-schedule).

   :::note
   Membership Lifecycle policies aren't applied to OUs specified here. Target OUs and groups are set in the respective policy.
   :::

9. Click **Add Triggers** in the Triggers area to specify a triggering criterion that, when met, starts the schedule. To add triggers, follow step 11 in [Create a Group Usage Service Schedule](groupusageservice.md#create-a-group-usage-service-schedule).
10. Click **Add Authentication** in the Authentication area to specify an account for running the schedule in the identity store. For details, follow step 12 in [Create a Group Usage Service Schedule](groupusageservice.md#create-a-group-usage-service-schedule).

    :::important Password Re-insertion Required
    Due to security enhancements, when you edit a schedule, you must re-enter the account password in the Authentication section, even if you aren't changing the authentication credentials. This is a required security measure to ensure password field sanitization across the product.
    :::

11. On the Create Schedule page, click **Create Schedule**.
12. On the Schedules page, click **Save**.

The schedule appears under **Membership Life Cycle**. For details, see [View the Schedules in an Identity Store ](manage.md#view-the-schedules-in-an-identity-store).
