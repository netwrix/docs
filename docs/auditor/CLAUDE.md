# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Product

**Netwrix Auditor** audits changes and activity across an IT environment: Active Directory, Group Policy, Exchange, file servers, SharePoint, SQL Server, Oracle, Windows Server, VMware, network devices, Microsoft Entra ID, Exchange Online, SharePoint Online, Microsoft Teams, and more. Administrators set up monitoring plans for data sources. The product collects who did what, when, and where into an audit archive and an SQL audit database, then offers search, reports, alerts, and a REST API.

Use "Netwrix Auditor" on first reference and "Auditor" after that. Name report packs "Netwrix Auditor for <data source>", for example "Netwrix Auditor for Entra ID".

## Versions

Documented versions: **10.6**, **10.7**, **10.8**, and **10.9** (latest). Edits to one version do **not** propagate to the others. Update each version the change applies to.

The sidebar is autogenerated from the folders (`sidebars/auditor/<version>.js`), so folder order and `_category_.json` control navigation. A new page needs no sidebar edit.

## Content Structure

Each version follows this layout:

| Folder | Purpose |
|---|---|
| `overview/` | Getting started, product editions, what's new |
| `requirements/` | Software, SQL Server, SSRS, ports, service account, working folder, long-term archive, supported data sources |
| `install/` | Install, upgrade, silent mode, virtual appliance, first launch, core services |
| `configuration/<datasource>/` | Prepare the monitored system (audit policies, permissions), one folder per data source |
| `admin/` | Monitoring plans (`monitoringplans/<datasource>/`), settings, reports, search, alerts, subscriptions, risk assessment, behavior anomalies, health status |
| `api/` | REST API overview, endpoints, ports, security, activity record and filter reference |
| `tools/` | Event Log Manager, Inactive User Tracker, Password Expiration Notifier, Audit Configuration Assistant |
| `addon/` | SIEM and vendor integrations |
| `kb/` | Knowledge base articles |

`index.md` and `whats-new.md` sit at the version root. `accessreviews/` and `accountlockoutexaminer/` also live in the Auditor folder.

### Data source pairs

Most data sources have two pages: one under `configuration/` that prepares the monitored system, and one under `admin/monitoringplans/` that creates the plan. When you change one, check whether the other needs the same change.

## Terminology

The product and its folders keep old names. Use the current name in documentation:

| Old or internal name | Use |
|---|---|
| Azure AD | Microsoft Entra ID |
| Audit Archive, Long-Term Archive, Short-Term Archive | Long-term archive; the working folder holds short-term data |
| Managed object | Monitoring plan (and its items) |
| Freeware, SMB, Standard, Advanced (internal edition names) | Free Community, Business Essentials, Enterprise Essentials, Enterprise Advanced |
| `adcr_db` | Audit database (the name is historical, not specific to Active Directory) |

## KB Articles

KB articles come from `docs/kb/auditor/` and are copied into each version's `kb/` folder at build time. Don't edit the copies. See `docs/kb/CLAUDE.md`.

## Images

Product images are in `static/images/auditor/<version>/` as `.webp` files. Reference them with absolute paths.
