# Entra ID Threats

Threat Manager monitors the following threats for Microsoft Entra ID. In the threat configuration list, they appear
under the Azure group.

## Application Permission Change

The Application Permission Change is when someone grants a sensitive or risky permission to an
application.

| Application Permission Change |                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition                    | Applications usually receive their permissions at creation time. In some cases, they need new permissions at a later stage. An attacker can exploit Microsoft Entra ID applications by adding the new permissions and using them for privilege escalation or persistence in your Microsoft Entra ID tenant. |
| Example                       | An application receives the "Directory.ReadWrite.All" permission or any permission that requires admin consent.                                                                                                                                                                                                                         |
| Trigger                       | Threat Manager creates a threat when an administrator grants admin consent to an application for a permission.                                                                                                                                                                                                                                                       |

## Compromised User Activity

The Compromised User Activity is when Microsoft Entra ID marks a user as "Confirmed Compromised" and that user
takes an action within your Microsoft Entra ID tenant.

| Compromised User Activity |                                                                                                                                                                                                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition                | The Compromised User activity threat involves detecting any activity from a user that Microsoft Entra ID marked as "Confirmed Compromised". Any action such users take is potentially malicious and you should review it immediately. |
| Example                   | A confirmed compromised user grants another user the "global administrator" role.                                                                                                                                                                         |
| Trigger                   | A confirmed compromised user performs any action in your Microsoft Entra ID tenant.                                                                                                                                                                       |

## Impossible Travel

The Impossible Travel is when a user logs in from one geographical location and then quickly (and
impossibly) logs in from another far away geographical location.

| Impossible Travel |                                                                                                                                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition        | Highlights accounts associated with multiple authentications from different geographical locations in a short period of time.                                                                                                                                               |
| Example           | A user logs in from a New York city, then 10 minutes later logs in from Moscow.                                                                                                                                                                                             |
| Trigger           | A threat triggers when a user logs in from two distant locations within a short period of time. By default, Threat Manager evaluates only user sign-ins. Threat Manager evaluates application and service principal sign-ins only when the **Trigger on Non-Human Identities** setting is on. |
| Settings          | **Trigger on Non-Human Identities** is off by default. When it is on, Threat Manager also evaluates sign-ins from applications and service principals for impossible travel, and Threat Manager tracks each service principal sign-in by its service principal ID or app ID.                      |
| Exclusions        | This threat doesn't offer the File Tag and Process exclusions, because location data exists only for authentication events.                                                                                                                                                         |

## New Applicaton Credentials

If an application suddenly gets a new set of credentials/client secrets, Threat Manager raises an
alarm as to why someone added these credentials.

| New Application Credentials |                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition                  | Application credentials are usually provided at the time of application creation or when a secret is close to its expiry. New credentials can be added on need basis as well. An attacker can exploit Microsoft Entra ID applications by adding new credentials and using them for privilege escalation or persistence within an Microsoft Entra ID tenant. |
| Example                     | Someone generated a new client secret for an existing application and used it for a cybersecurity product.                                                                                                                                                                                                                                                         |
| Trigger                     | Someone adds a client secret to an application.                                                                                                                                                                                                                                                                                                                 |
| Evidence                    | The expiration date and time of new application credentials and passwords appear in the viewer's local time zone. The evidence entries are Dangerous Expiry (key credentials) and Dangerous Password Expiry (password credentials).                                                                                                                         |

## Sensitive Role Changes

Sensitive Role Change is assigning a privilege role to an Microsoft Entra ID object.

| Sensitive Role Changes |                                                                                                                                                                                                                                                                            |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition             | The sensitive role changes threat detects when someone assigns a privileged role to an Microsoft Entra ID object. The privilege roles have a high level of access to Microsoft Entra ID objects. They can make unauthorized changes which can pose significant security risks. |
| Example                | A user gives another user the "Global Administrator" role.                                                                                                                                                                                                                 |
| Trigger                | When an Microsoft Entra ID object receives a privileged role.                                                                                                                                                                                                            |

## First Time Location

The First Time Location threat is when a user successfully signs in from a country or region they
have never used before.

| First Time Location |                                                                                                                                                                                                                            |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Definition          | Detects when a user successfully signs in from a country or region they have never used before.                                                                                                                            |
| Example             | A user who has only signed in from the United States signs in from a country they have never used.                                                                                                                         |
| Trigger             | A user successfully signs in from a new location. Threat Manager uses only successful sign-ins to learn a user's locations and to raise the threat. It ignores failed sign-ins.                                                      |
| Default settings    | Enabled, with severity Low.                                                                                                                                                                                                |
| Threat title        | First Time Location by \<user\> detected                                                                                                                                                                                     |
| Threat description  | \<user\> signed in from \<location\> for the first time. When it finds several new locations, it reads \<user\> signed in from \<N\> new locations including \<names\> for the first time.                                          |
| Evidence            | An entry titled First Time Location reads \<user\> signed in from \<location or N new locations including names\>, a location this user has not signed in from before.                                                               |
| Learning period     | The learning period is 30 days. A user who joined Threat Manager less than 30 days before the sign-in doesn't trigger the threat.                                                                                           |
| Applies to          | Events that carry location data, which are Entra ID sign-ins.                                                                                                                                                              |
| Rollup              | Rollup is on by default with a 24-hour window (1440 minutes) and you can configure it. The threat merges new locations from further sign-ins in the window.                                                     |
| Exclusions          | Perpetrator, Target, Client, Perpetrator Tag, Target Tag, and Location. Use Location to exclude specific countries or cities. This threat disables the File, Process, File Tag, and Affected Object DN exclusions. |

After an upgrade to 3.4, Threat Manager removes failed sign-in locations learned earlier. It deletes
locations with no successful sign-in and locations that no sign-in used within the event retention period.
The threat then suspends First Time Location alerting for 30 days while Threat Manager learns locations again from
successful sign-ins only.

## Authentication Methods Policy Weakening

The Authentication Methods Policy Weakening threat is when an attacker weakens the tenant-wide
Authentication Methods Policy.

| Authentication Methods Policy Weakening |                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Definition                              | Detects an attacker weakening the tenant-wide Authentication Methods Policy by enabling a phishable method, disabling a phishing-resistant method, or broadening a method's assignment to all users. This is a quiet, high-impact precursor to account takeover.                                                                                                                   |
| Example                                 | An administrator account enables the Sms method in the policy.                                                                                                                                                                                                                                                                                                                       |
| Trigger                                 | The Entra ID audit event Authentication Methods Policy Update shows a tracked weak method changed to Enabled, a tracked strong method changed to Disabled, or a tracked method's include targets gaining the all_users group. Threat Manager reports a target broadening only when the previous include targets didn't already contain all_users.                                              |
| Default settings                        | Enabled, with severity High.                                                                                                                                                                                                                                                                                                                                                         |
| Threat title                            | Authentication methods policy weakened by \<user\> detected                                                                                                                                                                                                                                                                                                                            |
| Threat description                      | The description reads "The authentication method \<method\> was enabled / disabled / broadened to all users." With several changes, it lists the first 3 and then "and N more".                                                                                                                                                                                                                                |
| Settings                                | **Tracked Weak Methods** (default: Sms, Voice) lists the methods whose change to enabled raises the threat. **Tracked Strong Methods** (default: Fido2, MicrosoftAuthenticator) lists the methods whose change to disabled raises the threat. Both are multi-value lists that use the Entra authentication method IDs. Broadening to all users applies to any method in either list. |
| Evidence                                | An entry titled Weakened Authentication Methods lists up to 5 changes (\<method\> was enabled, was disabled, or was broadened to all users), then "and N more". Evidence doesn't show the current configuration state of the policy.                                                                                                                                                |
| Attack path                             | The perpetrator followed by the affected method names (up to 3, then "and N more").                                                                                                                                                                                                                                                                                                  |
| Rollup                                  | Rollup is on by default with a 24-hour window (1440 minutes). In a rollup, repeated changes to the same method and change type keep only the latest.                                                                                                                                                                                                                                 |
| Exclusions                              | Authentication Method, Change Type, and Perpetrator. The Change Type values are WeakMethodEnabled, StrongMethodDisabled, and TargetBroadened. This threat disables the File, Process, File Tag, and Affected Object DN exclusions.                                                                                                                                                           |

## Security Policy Weakening

The Security Policy Weakening threat occurs when an Entra ID tenant-wide guardrail changes to a less restrictive setting.

| Security Policy Weakening |                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Definition                | Entra ID tenant-wide guardrails protect all accounts at once. They cover who may invite guests, whether users may consent to third-party apps, whether Security Defaults are on, and whether users may register applications. The threat fires when someone loosens one. This is a stealthy precursor to illicit-consent phishing, unmanaged external access, MFA-free sign-in, or app-registration persistence. |
| Example                   | An administrator changes the user consent setting to `Let Microsoft manage your consent settings`.                                                                                                                                                                                                                                                                                                             |
| Trigger                   | Someone loosens one of four monitored controls: Guest Invite Policy, User Consent for Apps, Security Defaults, or App Creation. Threat Manager doesn't report tightening a control.                                                                                                                                                                                                                                            |
| Default settings          | Enabled, with severity High.                                                                                                                                                                                                                                                                                                                                                                                 |
| Threat title              | Security policy weakened by \<user\> detected                                                                                                                                                                                                                                                                                                                                                                  |
| Threat description        | With one change, it reads "The \<policy\> tenant policy was loosened from 'old' to 'new'." Security Defaults reads "was disabled" and App Creation reads "was enabled". With 2 or 3 changes, it lists the policy names. With more, it lists 3 and then "and N more".                                                                                                                                             |
| Source audit events       | Update authorization policy and Update company settings (category AuthorizationPolicy), and Update security defaults (category Policy).                                                                                                                                                                                                                                                                      |
| Evidence                  | An entry titled Weakened Security Policies lists up to 5 changes, for example Guest invite policy weakened from 'X' to 'Y', User consent for apps weakened from 'X' to 'Y', Security defaults disabled, or User app registration enabled, then "and N more".                                                                                                                                                 |
| Attack path               | The perpetrator, a Weakened key, and the weakened policy names.                                                                                                                                                                                                                                                                                                                                              |
| Rollup                    | Rollup is on by default with a 24-hour window (1440 minutes). When someone weakens one control in several steps within the rollup, the threat shows one change from the original setting to the final setting.                                                                                                                                                                                                   |
| Exclusions                | Weakened Policy, Target Setting, and Perpetrator. Both Weakened Policy and Target Setting offer a fixed autocomplete list. This threat disables the File, Process, File Tag, and Affected Object DN exclusions.                                                                                                                                                                                                      |

The following table shows when each monitored control raises the threat.

| Control               | Reported when                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Guest Invite Policy   | The guest invite restriction becomes less restrictive. From least to most restrictive, the levels are `Anyone in the organization`, `Members and admin roles`, `Admin roles only`, and No one.                                                                                                                                                                                                                                    |
| User Consent for Apps | The setting moves to a less restrictive option. From most to least restrictive, the options are `Do not allow user consent`, `Allow user consent for apps from verified publishers, for selected permissions`, and `Let Microsoft manage your consent settings`. Threat Manager reports a move to a custom user consent policy when someone added a self-service consent policy. It doesn't report a move from a custom policy to a portal option. |
| Security Defaults     | It changes from enabled to disabled. Threat Manager doesn't report re-enabling it.                                                                                                                                                                                                                                                                                                                                                        |
| App Creation          | The tenant policy that lets users register applications changes from disabled to enabled.                                                                                                                                                                                                                                                                                                                                   |

The Target Setting autocomplete groups settings by policy. It lists the less restrictive settings that a
policy can take: `Anyone in the organization`, `Members and admin roles`, `Admin roles only`, the two lower user
consent options, Disabled (Security Defaults), and Enabled (App Creation). The most restrictive
settings don't appear because they can never be a target.
