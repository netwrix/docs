# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Product

**Netwrix Threat Manager** detects and responds to abnormal behavior and advanced attacks against Active Directory, Microsoft Entra ID, and file systems. It ingests event data from Netwrix Activity Monitor and Netwrix Threat Prevention, applies built-in threat analytics, and provides automated response via playbooks.

The product was formerly named **StealthDEFEND** (the legacy install path is `C:\Program Files\STEALTHbits\StealthDEFEND\`). Don't introduce this name into documentation — use "Netwrix Threat Manager" on first reference, "Threat Manager" thereafter.

## Versions

Documented versions: **3.0** (hidden), **3.1**, **3.2**, **3.3**, and **3.4** (latest). Edits to one version do **not** propagate to the others. Update each version the change applies to.

**3.3 uses the standard documentation zones** (see `.claude/references/documentation-section-guide.md`), so its folders differ from 3.0-3.2. When you carry a change between versions, map the path; don't assume it's the same. Pages moved in the 3.3 reorganization are redirected in `src/config/redirects/threatmanager-3.3.js`. If you move or rename a 3.3 page, add its old path there.

3.1 added:

- `administration/serviceaccounts.md` — Service Accounts dashboard (machine-learning-based service account discovery)
- `install/upgrade/upgrade3.1.md` — upgrade guide from 3.0 to 3.1 (PostgreSQL 14.13 → 14.20, then Threat Manager installer)

The sidebar is autogenerated from the folders (`sidebars/threatmanager/<version>.js`), so a new page needs no sidebar edit.

| 40 | `configuration/` | Configuration | Configuration menu: threat detection, threat response, policies (honeytoken), system settings, and `integrations/` (the console's Integrations menu pages Threat Manager needs to operate: AD and Entra ID sync, app tokens, credential profiles, email, folder settings, tag management, authentication providers) and `netwrix/` (Integration with Other Netwrix Products: Activity Monitor, Threat Prevention, Access Analyzer sending data to Threat Manager through app tokens) |

| 90 | `troubleshooting/` | Troubleshooting | Log files, updating passwords |
| 999 | `kb/` | Knowledge Base | Generated at build time (see below) |

The console's Integrations menu is split across two zones on purpose. Pages Threat Manager needs to operate live in `configuration/integrations/` (label "Integrations Interface", matching the console). The Netwrix products that send Threat Manager its data are also setup Threat Manager needs to operate, so they live in `configuration/netwrix/`. Connections to other systems (SIEM, Netwrix product databases) live in the top-level `integrations/` zone. `gettingstarted/threattypes/` (what can be detected) is different from `administration/threats/` (the Threats dashboard).

### Integration partners

Threat Manager receives event data from:
- **Netwrix Activity Monitor** — file system, AD, and Entra ID events
- **Netwrix Threat Prevention** — AD events via the Threat Manager Event Sink feature
- **Netwrix Access Analyzer** (formerly Enterprise Auditor) — sensitive data for file system context

## KB Articles

KB articles are not stored in the version folders. Their source is `docs/kb/threatmanager/`, and `scripts/copy-kb-to-versions.mjs` copies them into each version's `kb/` folder at build time (gitignored). Edit them in `docs/kb/threatmanager/` only. They are grouped in six category subdirectories:

- `configuration-and-administration/`
- `installation-and-upgrade/`
- `integration-and-event-collection/`
- `troubleshooting-and-diagnostics/`
- `licensing-and-system-issues/`
- `threat-management-and-operations/`

KB article frontmatter must include `knowledge_article_id` (Salesforce ID), `products`, `keywords`, `description`, and `title`. Example:

```yaml
---
title: 'Article Title'
description: 'One-sentence summary'
keywords: [keyword1, keyword2, Netwrix Threat Manager]
products:
- threat-manager
knowledge_article_id: kA0Qk0000001XXXXX
---
```

KB images live in `kb/0-images/` and are referenced with a relative path. Do not place KB images in `static/images/`.

## Images

Product images are in `static/images/threatmanager/<version>/` as `.webp` files. Reference them with absolute paths, e.g.:

```
/images/threatmanager/3.3/administration/serviceaccounts/dashboard.webp
```

## Threat Catalog Style

Each threat entry in the threat catalog (`gettingstarted/threattypes/*.md` in 3.3, `threats/*.md` in 3.0-3.2) follows this pattern:

1. H2 heading = threat name
2. One-paragraph definition — what the technique is and why it's dangerous
3. Optionally: a "Trigger" line for custom/behavioral threats
4. Admonitions (`:::note`) for configuration prerequisites where needed

Keep threat descriptions factual and concise. Don't editorialize.
